# Retail Database Design & Optimization

## Project Objective
Design and optimize a normalized retail database that manages customers, product categories, products, orders, order items, and payments. The database should support accurate business reporting and help a retail-store manager make informed decisions.

## Stakeholder
Retail store owner or manager.

## Problem Statement
A retail store needs an organized way to store customer, product, category, order, and payment information. Keeping this information manually or in unconnected files can cause duplicate data, errors, and difficulty preparing sales reports.

## Proposed Solution
Create a MySQL relational database with properly connected tables, primary keys, foreign keys, constraints, useful SQL queries, reporting views, and indexes.

## Main Features
- Store customer details.
- Store product categories and products.
- Record customer orders and ordered items.
- Record payment details.
- Generate sales and customer reports.
- Identify top-selling products and top customers.
- Use indexes to improve query performance.

## Success Criteria
- All tables are correctly related.
- Data is normalized and avoids unnecessary duplication.
- Invalid data is prevented through constraints.
- Queries return accurate reports.
- The database can be backed up and restored successfully.

## Data Source
All data used in this project will be fictional/sample data created for educational purposes. No real customer or business data will be used.
